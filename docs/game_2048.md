# Documentation : game_2048.c

## Vue d'ensemble

Le fichier `game_2048.c` implémente le **processus principal du jeu 2048**. C'est le cœur du système qui coordonne la logique du jeu, la communication inter-processus et la gestion multithread.

## Rôle principal

Ce processus est responsable de :
- **Créer et gérer** le processus d'affichage (fork)
- **Créer et coordonner** deux threads de traitement :
  - Thread **Move&Score** : Gère les mouvements et le calcul du score
  - Thread **Goal** : Vérifie les conditions de victoire/défaite et envoie les mises à jour
- **Lire** les commandes depuis le processus `main` via un pipe nommé
- **Synchroniser** les threads avec des mutex et des variables conditionnelles
- **Communiquer** avec le processus d'affichage via un pipe anonyme

## Architecture multithread

### Thread Move&Score
- **Rôle** : Traite les commandes de mouvement
- **Fonction** : `move_score_thread()`
- **Tâches** :
  1. Attend une commande via la variable conditionnelle `move_cond`
  2. Convertit la commande en direction de mouvement
  3. Exécute le mouvement avec `game_move()`
  4. Ajoute une nouvelle tuile si un mouvement a été effectué
  5. Réveille le thread Goal pour vérifier l'état du jeu

### Thread Goal
- **Rôle** : Vérifie les conditions de fin de partie et envoie les mises à jour
- **Fonction** : `goal_thread()`
- **Tâches** :
  1. Attend qu'un mouvement soit effectué via `goal_cond`
  2. Vérifie si la partie est gagnée (`game_is_won()`)
  3. Vérifie si la partie est perdue (`game_is_lost()`)
  4. Envoie l'état du jeu au processus d'affichage via le pipe anonyme
  5. Envoie un signal au processus d'affichage pour le réveiller

### Thread principal
- **Rôle** : Lit les commandes et les transmet aux threads
- **Tâches** :
  1. Crée le processus d'affichage (fork)
  2. Crée les deux threads
  3. Lit les commandes depuis le pipe nommé
  4. Transmet les commandes au thread Move&Score
  5. Gère l'arrêt propre du système

## Communication inter-processus

### Avec le processus main
- **Mécanisme** : Pipe nommé `/tmp/2048_main_pipe`
- **Direction** : `main` → `game2048` (lecture)
- **Message** : `CommandMessage` contenant un `CommandType`

### Avec le processus display
- **Mécanisme** : Pipe anonyme créé avec `pipe()`
- **Direction** : `game2048` → `display` (écriture)
- **Message** : `DisplayMessage` contenant l'état complet du jeu
- **Signaux** : `SIG_UPDATE_DISPLAY` pour réveiller le processus d'affichage

## Synchronisation

- **Mutex** : `game_mutex` protège l'accès à `shared_game_state`
- **Variables conditionnelles** :
  - `move_cond` : Réveille le thread Move&Score lorsqu'une commande arrive
  - `goal_cond` : Réveille le thread Goal après un mouvement
- **Variables de contrôle** :
  - `command_ready` : Indique qu'une commande est prête à être traitée
  - `game_running` : Contrôle la boucle principale et les threads
  - `pending_command` : Stocke la commande en attente

## Fonctionnement détaillé

1. **Initialisation** :
   - Initialise le générateur aléatoire
   - Crée le pipe anonyme
   - Crée le processus d'affichage (fork + execl)
   - Initialise l'état du jeu avec `game_init()`
   - Envoie l'état initial au processus d'affichage

2. **Création des threads** :
   - Crée le thread Move&Score
   - Crée le thread Goal
   - Attend que les threads soient prêts

3. **Boucle principale** :
   - Lit les commandes depuis le pipe nommé
   - Transmet les commandes au thread Move&Score via les variables partagées
   - Gère l'arrêt propre avec CMD_QUIT

4. **Nettoyage** :
   - Attend la fin des threads avec `pthread_join()`
   - Ferme les pipes
   - Attend la fin du processus d'affichage avec `waitpid()`

## Gestion des signaux

- **cleanup_handler** : Gère SIGINT et SIGTERM pour un arrêt propre
- Envoie SIGTERM au processus d'affichage lors de l'arrêt

## Points techniques

- Utilise `pthread` pour le multithreading
- Utilise `fork()` et `execl()` pour créer le processus d'affichage
- Utilise `dup2()` pour rediriger `stdin` du processus d'affichage vers le pipe
- Gère correctement les interruptions par signal (EINTR) lors des opérations de lecture
- Utilise `nanosleep()` pour attendre que les threads soient prêts
